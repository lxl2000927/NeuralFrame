# Enhanced 汉化补全 1.11：统一组件库与独立在线更新

本版继续基于 Enhanced 2.3.0，保留 zh1.10 已合入的上游提交 bb72b7c、现有汉化/F8 面板、运行时检测、版本锁定、变更预览及原版恢复。

## 使用方式

关闭管理器，将 `Enhanced-zh1.11-patch.zip` 解压覆盖当前 zh1.10 管理器目录，合并 `resources`。更早的版本建议将完整便携包解压到新目录使用。不要解压到游戏目录。

进入“插件 → 组件库与独立更新”：

1. 首次使用将随包组件复制进持久组件库；以后升级软件会追加随包快照，保留已下载版本和游戏选择。
2. 点击“检查在线更新”，展开对应组件的“版本、来源与下载”，下载需要的版本。支持进度、取消、SHA-256 校验及失败清理。下载不会写入游戏。
3. 选择目标游戏，再选择“待应用版本”。这个选择优先于档位页和额外插件的全局设置；选回“沿用安装路线”可恢复路线的默认版本策略。
4. 点击“预览并应用选择”，核对实际文件差异后确认。需要先通过现有安装路线启用相关功能；组件更新不会自动启用已关闭的神经渲染或帧生成。
5. 重启游戏后，通过游戏组件清单中的运行时检测核对实际加载。组件库显示的是磁盘文件匹配，不代表已经在游戏中生效。
6. “回滚上次组件更新”按文件快照恢复上一版，也经过预览和版本锁检查；原有“一键卸载并恢复原版”继续可用。

## 已实现

- 组件库保存于 `%APPDATA%\dlss5-swapper-enhanced\component-library-v1`，与软件目录分离。版本以组件类型和完整文件 SHA-256 区分，多版本共存，相同二进制去重。
- 统一登记 SR、FG、NR、RenoDX、两种 MFG 插件、Feeder、ReShade、OptiScaler、预加载器、汉化适配层和 F8 叠加层。分别显示发行版本、文件版本、来源、指纹和适配状态。
- 每款游戏独立保存版本选择。普通安装和档位应用也沿用该选择，包含显式选择较旧版本的情况；选择记录本身不修改游戏。
- 旧模型库的合法模型迁入统一库；从统一库下载的 NR 也会出现在原模型页。
- 在线源为配置好的 GitHub 仓库：mavismmg/MFGAdaUnlock-RenoDx、dashdogy/MFG-Unlocker、RankFTW/rhi-repo、jlrouzies-fr/DLSS5-Feeder、Dagherbou/OptiScaler_DLSSNR。RankFTW 是第三方分发仓库，不是 NVIDIA 官方发布源。
- 在线检查按需触发，不后台轮询。查询失败保留上次缓存并明确标记过期；缺少 SHA-256 的资产不允许直接下载入库。
- 下载包限制大小、路径及解压总量，拒绝路径越界、符号链接、重复大小写路径和同名不同内容组件。导入、应用和预览确认时均检查文件。
- 组件替换沿用原始备份，独立更新另存上一版快照；游戏运行中会阻止写入。版本锁继续拦截组件变化。

## 适配边界

“有新版”不等于“可以直接替换”。当前可独立选择并应用的是通过适配检查的 SR、FG、NR、RenoDX 和 MFG 组件；NR 应用前检查实际 GPU 架构，FG 保留当前解锁器支持的版本范围。

未知版本的原生插件允许下载保存，但在验证中文桥接 ABI、配置协议和组件依赖前显示“等待适配”，不会覆盖当前中文面板。例如本次实际下载的 MFG RenoDX 1.8.2 被正确拦在应用之外；Universal 1.7.0 的文件与已有适配版本一致，可直接选择。

Feeder、ReShade、OptiScaler 和旧游戏预加载器仍由安装路线成组应用，不开放随意拆换宿主、图层和加载器。汉化层及 F8 桥接继续随软件维护。它们已统一登记；需要新的协议/ABI 支持时仍须更新管理器的适配代码。本版没有宣称所有新插件都能无需适配立即应用。

# Enhanced 汉化补全 1.7：运行时检测

本版接续 1.6 的组件清单、变更预览和版本锁定。在“DLSS 5 + 补帧档位”选择游戏后，点击“检测运行状态”；“查看组件”也会触发一次检测。

## 能检测什么

- 按实际 EXE 路径匹配 Windows 游戏进程，显示 PID 与启动时间。启动器、其他同名目录及旧游戏实例不能冒充当前游戏。
- 读取当前进程的相关模块，组件清单显示“已加载”“其他路径”“模块表未发现”“游戏未运行”“读取受限”。配置与着色器资源单独标明不属于进程模块。
- DLSS5：解析本次启动日志中的 NR 成功执行帧遥测，区分初始化、曾经生效、正在执行、关闭、暂未执行、失败和记录过期。`ENGAGED` 单次记录显示“本次运行已生效”；只有新鲜的成功执行窗口才显示“正在执行神经渲染”。仅勾选开关、加载 DLL、调用 Evaluate 接口均不能证明成功执行。
- MFG：读取 RenoDX 的 `slDLSSGGetState` 呈现报告，以及 RTXMFG 状态文件中的 PID、进程出生时间、状态采样年龄、错误码和实际呈现计数；显示请求倍率、已应用请求、待切换、重启要求与补帧输出。
- 提供程序在两次查询之间呈现了几帧，不等于已经实测屏幕倍率。插件输出 FPS 明确标为插件报告，不使用“基础 FPS × 请求倍率”伪造实测 FPS。
- 展开“判断证据”可查看原始日志行、来源路径和时间；支持查看实际加载模块路径。
- 检测到游戏启动时间早于最近一次应用，会提示重启；晚于应用则确认已重新启动，再逐项检查模块。

## 刷新与性能

默认按需检测。可选每 5 秒自动刷新；窗口最小化、后台标签或离开页面时停止查询，回来后继续。检测请求合并并有短缓存；运行检测不重新计算组件 SHA-256，不轮询 GPU。日志只读末尾最多 256 KiB，并限制临时状态目录扫描范围。

超过 30 秒没有新的执行遥测，绿色生效状态会变为“本次记录已过期”；当前会话没有执行遥测时，明确显示“已加载，等待运行证据”，不将历史成功冒充当前生效。某些旧插件只在状态变化时写日志，无法仅凭它们持续确认执行，需要在游戏内诊断面板交叉核对。

## 当前范围与限制

- 当前为 Windows 进程模块与现有插件遥测的只读检测，不注入新探针、不扫描或修改游戏进程内存、不修改游戏 DLL。
- 游戏权限高于管理器、受保护进程、手动映射 DLL、多实例、插件不输出遥测等情况会给出具体原因，不能保证所有游戏/插件都能确认正在生效。
- 32 位 Feeder 的 64 位宿主不是主游戏进程，其独立模块不会冒充主进程已加载；仅在日志能归属当前会话时使用执行证据。
- ReShade 叠加层连接、保存的配置值、兼容性评估及磁盘安装成功均不作为运行生效证据。顶部运行时检测是本页的当前执行判断；原有兼容性/预算卡仍是静态评估。

## 版本锁定的范围

锁定记录当前磁盘组件的完整哈希，拦截更换、删除或新增组件；不涉及组件更换的参数调整仍可应用。如果某次参数应用同时要求升级运行库，也会被拦截，需要先查看原因。组件清单会指出被游戏更新或其他工具改变的文件。

游戏自带或本管理器部署的已识别二进制组件纳入锁定，管理器自有的共享 Vulkan 图层也会尊重其他游戏的锁。单独安装／移除 F8 叠加层时同样检查所属游戏是否锁定。

锁定不额外复制一套 DLL，也不阻止游戏更新器或其他管理器改文件，不承诺自动下载旧版本。它防止本管理器在应用时悄悄换掉组合。明确确认“恢复原始文件”并成功完成后，会解除该游戏的锁；其他游戏的共享组件锁仍受到保护。
