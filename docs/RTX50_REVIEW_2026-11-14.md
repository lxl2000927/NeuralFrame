# RTX 50 原生多帧生成核对（2026-11-14）

## 结论与产品表述

NeuralFrame 集成社区与开源项目提供的神经渲染、帧生成和运行库组件。RTX 20 / 30 / 40 的扩展能力按具体组件、API、驱动和游戏输入判断；RTX 50 已有原生多帧生成能力，插件承担倍率、动态模式及面板控制，不能统称为“解锁 RTX 50”。模型的 CUDA 架构匹配、文件已部署、进程已加载与实际持续执行是不同证据层级。

硬件档位只是参数预设。用户在 RTX 50 上选择省显存档位，不能因此开启 Ada 专用修补；在 RTX 40 上选择 RTX 50 参考档位，也不能因此把物理显卡当成 Blackwell。现有游戏配置不会在刷新、检测或本次升级时自动改写。

## 本次落实

1. **MFG 修补基于实际显卡。** `mfg-manager.js` 的 RenoDX 与 OptiScaler ASI 写入路径均以实际 GPU 架构选择 Ada 专用修补。RTX 50 不因借用 40 系档位而启用修补；RTX 40 不因手选 50 系档位而误关所需修补。显卡未知时采用不启用 Ada 专用修补的保守配置，并提示先确认硬件。
2. **清除换显卡后的残留。** 不使用 Ada 修补时同时清零已有的 V3 stability/inpaint 标志，保留倍率和 Dynamic 控制。禁用 TemporalFix 不再被反推为“这就是 Blackwell 硬件”。
3. **能力与生效分开。** RTX 50 的 x2/x3/x4 及 RTX 40 的原生 x2 显示“原生支持（需游戏验证）”，不再仅凭 GPU 型号显示“已验证可用”或“已启用零冲突模式”。既有文件状态和运行诊断继续独立展示。
4. **游戏页修正文案。** MFG 模块不再宣称全系显卡、全部游戏均兼容；RTX 50 档位统一显示原生多帧生成控制并包括笔记本。旧的 `rtx50_desktop` 配置 ID 保留，数值参数与已保存运行库选择不变。
5. **Encore 连写型号。** 修复 `RTX 5090D`、`RTX 5070Ti`、`RTX 4080Super` 被 GPU 名称正则错误拒绝；不扩大到未列明系列、不改变 API/位数/鸣潮独立路线限制。
6. **独立路线与 RenoDX 的支持范围分开。** 鸣潮实际部署的 MFG-Unlocker 经文件指纹确认为已接入的 1.7.0 / 1.7.1 时，RTX 20 / 30 显示社区实验性支持及游戏验证要求。未知文件、仅名称或版本相同的 DLL，以及 RenoDX Ada 路线不借用这份结论。只修正状态评估，不扩大安装许可或宣称原生支持。
7. **首次使用不误判为永久不兼容。** 仅对鸣潮独立路线的 RTX 20 / 30，尚未安装或加载器指纹未知时显示“独立方案待校验”，各倍率保持待确认；不赋予原生能力或已支持模式。DLL 冲突、API 与位数错误仍优先显示不兼容。其他游戏和安装路线的评估不变。

鸣潮仍使用现有独立加载链路。此次没有修改启动器清单、游戏原版 DLSS/Streamline 文件、独立加载参数映射或组件指纹；RenoDX/ASI 的安全修补决策不替代鸣潮独立组件内部的 GPU 检查。

## 验证与实际边界

新增 `test/rtx50-native-policy.test.js` 覆盖 RTX 50 桌面/笔记本、交叉选择档位、未知 GPU、重复应用与残留清除、倍率/运行库/调校保留、Encore 型号与位数边界，以及鸣潮 RTX 20 / 30 按实际独立加载器指纹判定的状态。部署用例在临时游戏目录调用实际写入流程及组件指纹校验，不修改真实游戏目录。

这些回归验证配置、文件和状态语义，不能代替 RTX 50 真机游戏测试。未声称在 RTX 50 上完成实际画面、帧率、延迟、神经渲染效果或所有游戏兼容性验证。ANR 以及其他新版本的新功能需另行审查接口、部署归属与回滚后才能开放。
