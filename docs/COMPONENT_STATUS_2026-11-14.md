# 组件应用条件说明（2026-11-14）

组件页分别展示本地文件状态和应用条件。文件入库、版本名称相同、CUDA 架构匹配，都不会自动授予安装权限。实际游戏能否使用仍由游戏页预览检查，运行诊断负责显示是否已生效。

## 应用条件

| 状态 | 判断依据 | 下一步 |
| --- | --- | --- |
| 可选组件 · 游戏页预览 | 当前规则允许选择该类组件或已验证的配套文件 | 未下载时先入库，然后在游戏页选择、预览 |
| 推荐版本 / 已适配版本 · 游戏页可选 | MFG / Encore 的文件或发布包指纹命中已适配引擎记录 | 在游戏页的引擎版本选项选择、预览 |
| 配套安装 · 游戏页管理 | 当前安装路线使用的宿主、运行库或加载器组合 | 通过游戏页安装路线统一准备与应用 |
| 需校验文件身份 | 只有未知发布包信息，或模型架构仅来自上游目录 | 下载并校验；命中适配记录后再选择，否则使用配套版本 |
| 此版本未验证 · 暂不可用 | 已取得文件身份，但没有对应的协议、面板、依赖适配记录 | 改选配套或已适配版本；重复下载不解除限制 |
| 此版本不能单独替换 | 上游单独发布的成组组件版本，当前没有独立替换入口 | 查看配套版本；下载此版本只会入库 |
| 显卡架构不匹配 | 模型架构记录不包含本机 CUDA SM | 选择支持本机架构的模型；仅目录依据会额外标明 |
| 未识别显卡架构 | 本机 CUDA SM 未识别，无法判断模型是否适用 | 在设置中核对硬件识别和驱动 |
| 模型架构待确认 | 本机架构已知，但目录没有该模型的 CUDA 记录 | 下载或导入后，在游戏页预览实际 DLL 检查结果 |
| 文件异常 · 需修复 | 已入库文件缺失或大小异常 | 校验、重新下载或重新导入；修复后仍需重新核对适配条件 |
| 软件内置 · 无需单独安装 | 随 NeuralFrame 维护的内置组件 | 使用对应功能；新版本随软件更新 |

“此版本未验证”表示尚未完成适配验证，不等于实测确认不兼容。“目录标注”也不等于实际 DLL 已核验。

## 界面与实现

- 列表在状态下直接显示简短原因和下一步；点击状态打开侧栏，完整展示能否应用、原因、依据、下一步，以及模型的本机 / 所需 CUDA 架构。
- 筛选器和列表、侧栏共用同一状态判断；历史版本折叠、来源区分和模型身份合并规则保持原样。
- 下载按钮区分“下载入库”“下载并校验”“下载留存”；已有缓存使用“校验缓存”。这些操作都不自动应用到游戏。
- 可选或配套可应用状态使用绿色；待确认、不能单独替换和内置维护状态使用中性色；未验证版本、硬件不匹配、文件异常使用警示色。列表与详情保持一致的含义。
- 后端 `assessment` 只补充说明，原有 `kind` / `ready` 安装限制保持不变。已适配 MFG / Encore 通过游戏页引擎选择安装，不能作为任意 DLL 独立替换。
- 不新增联网查询或扫描 DLL；沿用现有目录、指纹、缓存状态和硬件结果。

## 上游来源纠正

`runtime-catalog.json` 的 `upstreams` 用于来源显示，`repository` / `url` 继续只承担既有下载与校验职责。列表、筛选与详情不再将 NeuralFrame 的配套包下载仓库作为第三方组件上游；详情移除配套包发布方区块。未记录上游时明确显示“上游未记录”，内置组件显示“软件内置”。

NR 配套模型沿用 SmarterGamers 来源，RankFTW 模型保持独立；DLSS / Streamline 指向 NVIDIA 项目，RenoDX 同时区分 clshortfuse 项目和 RankFTW 发布源，其余组件显示各自原项目。上游项目标识不构成对具体二进制是否被修改过的判断。原有下载地址、文件指纹与缓存标识均未变化，构建脚本会保留这些显示元数据。

新增来源回归包含目录分类与筛选、历史记录回退、外链允许范围、缓存身份不变及真实目录的 Electron 显示检查。46 项相关测试通过；来源 UI 检查覆盖 10 组上游，确认列表、筛选、详情均不再出现管理器仓库。证据：`D:/NeuralFrame-research/component-upstreams-20261114/`。
