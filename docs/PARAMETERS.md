# 画质、补帧与叠加层参数手册

适用于 NeuralFrame **0.1.3**。先看参数属于哪个引擎。以「3×」为例，ANR 用它限制最多能生成几帧，独立 XeMFG 用它请求固定倍率，OptiScaler 插件则由游戏内的宿主菜单调节。游戏页的设置要经过预览和应用；F8 的实时控件由游戏里已加载的插件提供。

## 安装环境

| 参数 | 可选值与作用 |
| --- | --- |
| 可执行文件 | 选实际渲染游戏的 EXE。一个目录可能同时有启动器、DX11 和 DX12 程序；组件探测和预览针对选中的程序。 |
| 渲染 API | 默认自动检测。可指定 DirectDraw、DirectX 8 / 9 / 10 / 11 / 12、Vulkan、OpenGL。手动值用于匹配游戏实际启动模式，游戏本身的渲染器仍在启动参数或游戏设置中选。 |
| 渲染后端 / 安装方式 | 先选 ReShade、OptiScaler、RTX Encore 或页面列出的专用引擎，再选可用方式。ReShade 下可见原生 DLSS、Feeder 或 RenoDX DLSS Tool 等选项，取决于 EXE 位数、API 与输入。 |
| ReShade 加载文件 | 适用路线可在 `dxgi.dll`、`d3d11.dll` 之间选择，决定游戏通过哪个文件加载 ReShade。可选项受渲染接口限制。 |
| OptiScaler 构建 / 引擎版本 | 指定部署的宿主或插件版本。历史版能否使用取决于对应文件指纹与设置协议；更换版本前先查看现有配置是否兼容。[组件来源](COMPONENTS.md) |

## 硬件档位与神经渲染

### 档位给游戏写入什么

| 档位 | 参考分辨率 | NR 工作分辨率 / 处理遍数 / 最多工作集 | 默认运行库组合 |
| --- | --- | --- | --- |
| RTX 40 笔记本 | 1920 × 1080 | 75% / 1 遍 / 4 组 | 基准组合 |
| RTX 40 桌面 | 2560 × 1440 | 100% / 1 遍 / 8 组 | 基准组合 |
| RTX 50 | 3840 × 2160 | 100% / 1 遍 / 8 组 | 更新组合 |

管理器依次采用手动选择、游戏部署记录、已有默认值、自动识别。自动匹配时，显存低于 10 GiB 的 RTX 40 桌面卡使用笔记本参数，RTX 50 笔记本沿用 Blackwell 档。其他未匹配设备显示省显存参考参数；能否部署继续按实际硬件检查。表中分辨率是档位参考，游戏输出分辨率仍在游戏中选。[档位选择逻辑](../src/core/hardware-profile.js) · [档位与模型定义](../src/core/neural-models.js)

| 参数 | 用途与读法 |
| --- | --- |
| 神经渲染模式 / 模型 | **Off** 关闭 NR；**Legacy Model** 选择早期 310.8.0-RTX40 基线；**Latest Compatible** 使用兼容模型选择。模型下拉框能指定具体构建。核对来源、DLL 指纹及实际显卡的 `sm_` 架构。[模型对照](COMPONENTS.md#模型列表怎么看) |
| 运行时栈 | 基准组合含 DLSS SR / FG 310.9.1、Streamline 2.13 和 Feeder 1.17；更新组合为 310.9.16、2.14.16 和 1.19。独立选择 NR 模型。《鸣潮》使用游戏原版运行库，在该路线只读。 |
| NR 挂接点（`NRHookPoint`） | 决定在图像处理的哪个阶段调用模型，三个档位均按超分后处理。不同插件的配置枚举独立，不能跨 INI 直接套数字。 |
| 工作分辨率（`NRResolutionScale`） | 模型处理图像的尺寸比例。降低比例会减少送入推理的像素，细小纹理和文字的变化可在同一场景比较。与游戏输出分辨率、DLSS 输入比例分别设置。 |
| 遍数（`NRPasses`）/ 工作集（`NRMaxWorksets`） | 遍数决定对一帧重复处理几次。工作集决定最多缓存几组渲染表面，较大的池可复用更多表面，也可能占用更多显存。《鸣潮》的独立插件只映射其协议支持的档位项。 |
| 重置神经渲染调校 | 在下次预览并应用时恢复当前档位的调校默认值。普通的重新应用会保留游戏内调整过的外观参数。 |

### 预览中的自动配置项

在 ReShade 路线的文件预览中，还可能看到以下 INI 项。它们由档位、硬件和加载方式共同决定，适合用来核对两套配置为什么不同。

| 配置项 | 本版的写入含义 |
| --- | --- |
| `EnableHooks` / `NREnableUpscaling` | 区分原生 Streamline 与 Feeder 输入。Feeder 路线上由 Feeder 负责送入画面，管理器为适配的 RenoDX 配置写入 2 / 0。 |
| `NRFollowInputRes` / `NRResolutionScale` | 档位以 0 关闭自动跟随输入尺寸，然后写入自己的比例。切档时工作分辨率和工作集一起更新。 |
| `NRAutoMask` / `NRUICorrection` | 新建或重置配置时均写 0，分别控制自动遮罩和界面校正。可调性取决于所载插件。 |
| `NRMVecScaleX/Y` / `NRDiffuseWhiteNits` | 运动矢量两个轴的默认倍率均为 1；漫反射参考白点初始为 203 尼特。 |
| `ForceMultiplier` / `DynamicMFG` | 前者记录选择的倍率，后者启用插件的动态策略。实际生效值应在本次会话核对。 |
| `AdaptiveQualityProfile` / `TemporalFix` / `BlackwellFrameworkKernels` | 前者选择社区插件的自适应插值配置，后两者为相应硬件的兼容选项。实际 RTX 50 使用原生控制，这些 Ada 修补会关闭。 |

## 帧生成

倍率按包含原始帧的总数显示。例如，3× 的目标是一张真实渲染帧配最多两张生成帧。游戏可能在菜单、过场或特定场景暂停补帧。要估算实际倍率，用同次运行、同一时段的插件输出 FPS 除以基础 FPS。

| 引擎 / 参数 | 值与用法 |
| --- | --- |
| NVIDIA DLSS MFG · 补帧倍率 | 通用页面提供关闭、2×、3×、4×。2× 对应一张插入帧。RTX 50 原生支持多帧生成；其他 RTX 要看对应插件和游戏。《鸣潮》可选动态，按运行库与刷新率调节。已由游戏面板保存的跟随游戏、5× 或 6× 可按现状显示。 |
| NVIDIA · 帧生成输入源策略 | `QualityGuardMode=0` 使用原生输入；`2` 用于 HDR UI 保护。开启 HDR 后遇到界面闪烁时可对比两种设置。《鸣潮》独立路线固定使用游戏输入。 |
| ANR FG · 倍率上限 | 完整包与 Add-on 均可设 2×–6×，首次界面显示 6× 上限。3× 会把 `max_generated` 设为 2。需要游戏内启用 DLSS 帧生成输入。 |
| ANR FG · 切镜保护 / 联用 NR | 切镜保护默认开，用于处理场景突变时相邻两帧不连续的问题。「同时启用 DLSS 神经渲染」仅在完整包、原生 DLSS 超分和兼容 NVIDIA GPU 等条件下可用。NR 默认关。 |
| Dlssg_for_sm86 · 引擎 / 倍率上限 | DLSS 模式 2×–6×，XeSS 模式 2×–4×，首次为 DLSS、4×。从 5× 或 6× 切到 XeSS 时，页面将上限调为 4×。标准版和三角洲专版按各自 EXE 与 API 部署。 |
| 独立 XeMFG · 固定倍率 | 2×–6×，首次为 2×。选择后预览并应用，重启游戏，按 Backspace 查看输入与状态。已有配置如使用动态模式，可明确切换为固定倍率。 |
| XeMFG 插件 / OptiFG · 输入和输出 | 插件使用 OptiScaler 的 Upscaler 输入，输出分别为 Intel XeFG 或 AMD FSR FG。在游戏中启用宿主可读取的时间超分，用 Insert 打开宿主菜单查看状态和调节其提供的选项。OptiFG 会关闭宿主已启用的 DLSS NR，并在自动或 DLSS 超分后端上改用 FidelityFX。 |
| AFMF | 由 AMD Software 按游戏启停，管理器提供符合条件时的入口。RX 6000 系列需要独占全屏。 |

## RTX Encore

入口为「游戏 → 画质与补帧 → 安装与运行环境 → RTX Encore」。这些设置适用于符合要求的离线 RTX 游戏。改好后点「预览并应用 Encore 配置」，重启游戏，按 Insert 查看。

| 参数 | 取值 | 对画面或运行的影响 |
| --- | --- | --- |
| DLSS 帧生成倍率 | 关闭、2×–6× | 指定 Encore 的生成倍率。5×、6× 标为实验性；缺少独立 HUD 输入时，界面也可能参与插帧。 |
| 运动估计来源 | 优先游戏矢量、Encore、Shader（vort）、Optical Flow 质量 / 速度 | 决定如何估算物体位移。优先游戏矢量时，缺失输入会回退到估计；可在镜头平移、物体边缘或 HUD 附近比较重影。 |
| 附加超分引擎 | 关闭、NVIDIA DLSS；2.5.0 另有 MWSR、NIS、FSR 1 | 适用于没有原生 DLSS SR 的目标。附加 DLSS 采用游戏分辨率 / DLAA；后三项按单帧做空间缩放。DX11 / DX12 空间缩放须使用同宽高比的小窗口，单维最多放大两倍。 |
| 空间超分锐化 | 0–100%，默认 30% | 增强缩放后的边缘。看文字和高对比轮廓是否出现亮边，再决定是否继续提高。 |
| 空间超分抗锯齿 / 处理位置 | 关闭、SMAA 1x、FXAA 3.11；缩放前 / 后 | 缓和空间缩放时的锯齿，HUD 也参与。SMAA 另有低、中、高、极高四档。 |
| 原生 DLSS 超分比例 | 跟随游戏、DLAA、极高质量、质量、平衡、性能、超高性能、自定义 | 只在游戏已有 DLSS SR 时显示，控制送入超分的渲染尺寸。自定义按整数百分比填写，2.3.0 为 50–100%，已适配的 2.4.1 起为 33–100%。 |
| Encore 神经渲染 / 模型 | 关闭或启用，选择模型文件 | 可单独开启。当前接受 310.8.0 / 310.9.16 模型协议，还会检查模型文件身份与实际 GPU 架构。 |
| NR 工作分辨率 / 自定义比例 | 跟随渲染、输出分辨率、质量、平衡、性能、超高性能、自定义 33–100% | 只决定 NR 推理的工作尺寸。新配置自定义值为 75%；已有 JSONC 缺少比例时按引擎默认 67% 读取。 |
| NR 处理次数 / 逐遍处理位置 | 1–4 遍；每遍可跟随全局、超分前、超分后或最终画面 | 新配置 1 遍。逐遍位置需已适配的 2.4.1 或更高版本。混合位置要求兼容原生 DLSS；超分前实验路线与 RR / DLAA 不兼容。 |

## 鸣潮独立加载

「神经渲染高级参数」控制独立 MFG 插件。桌面端保存后要预览、应用并重启游戏。游戏自带的 SR / FG / Streamline 在对应页面只读。

| 参数 | 取值与作用 |
| --- | --- |
| 神经渲染模型策略 | Model A、B、C，对应引擎策略 0、1、2。实际使用的 `nvngx_dlssnr.dll` 仍由「神经渲染模型」选择。 |
| 结构强度 / 色调强度 | 各 0–2，界面步长 0.05，档位默认皆为 1。前者调纹理与轮廓处理程度，后者调明暗色调的处理程度。 |
| 人物强度 / 人物遮罩 | 强度 −1–2，步长 0.05；档位默认 −1。遮罩开关决定是否单独处理人物区域，手工调整时可在同一人物近景对照。 |
| 插件诊断日志 | 适配的 1.7.1 提供开关，用于定位插件初始化或运行状态。该开关仅保存在本机。 |
| 重置神经渲染调校 | 恢复当前档位的性能和外观默认值。已经调好人物与色调时，可只应用需要改动的参数。 |

## Home 单遍调校

在加载对应 RenoDX 的游戏中按 Home，进入「单遍神经渲染」。四组预设均使用一遍推理。表中数值按面板的「强度 / 结构 / 局部色调」顺序排列。

| 预设 | 工作分辨率 | 强度 / 结构 / 局部色调 | 用途 |
| --- | --- | --- | --- |
| 省卡强化（Balanced） | 75% | 1.35 / 1.30 / 1.22 | 在较低推理尺寸上增强细节。 |
| 高帧优先（Performance） | 67% | 1.30 / 1.25 / 1.18 | 进一步降低推理像素数量，适合对比 GPU 开销。 |
| 质感优先（Quality） | 100% | 1.55 / 1.45 / 1.35 | 以完整尺寸做更强的结构和色调处理。 |
| 原厂标准（Standard） | 75% | 1.00 / 1.00 / 1.00 | 关闭额外外观调整，作为同场景比较的起点。 |

| 单项参数 | 取值与作用 |
| --- | --- |
| 强度 / 结构 / 局部色调 | 各 0.4–2.0。依次控制整体处理强度、纹理与轮廓、局部明暗。 |
| 工作分辨率 | 50–100%。降低时优先观察细小文字、头发和远处纹理的变化。 |
| 外观调整 / 细节 / 色调 / 颜色 | 打开 Look 后，三项各可设 0.4–2.0，用来分别调节外观层的细节、调子和色彩。 |
| 锐化 / 稳定 / 回拉 | 有 Feeder 配置时显示。锐化和稳定均为 0–1；稳定控制静止区域沿用前帧输出的程度。回拉 0 / 1 / 2 分别使用双线性、FSR 1、DLSS SR 将工作画面放大。 |

面板会提示当前能否实时写入。出现「restart to apply」时，更改写入配置，重启游戏后查看。[单遍控件与预设原值](../overlay/single-pass-tuner.hpp)

## F7 监控与 F8 实时控制

**F7 显示模式**为隐藏、精简、详细，可固定在左上、右上、左下或右下。精简模式显示 FPS、显存和可用的延迟。详细模式另列 ReShade 帧时间、1% Low，具备整卡数据与进程预算时还列进程占用。

| F7 读数 | 如何解读 |
| --- | --- |
| DXGI FPS / ReShade FPS | 优先使用可取得的 DXGI 呈现计数，回退为 ReShade 采样。标签标出采样来源；核对生成倍率还需要插件报告的基础帧和输出帧。 |
| ReShade 1% Low / frame time | 1% Low 取近期最慢 1% 帧间隔的平均值换算为 FPS，样本不足 100 时显示 `--`。frame time 以毫秒显示该采样窗口的平均帧间隔。 |
| VRAM / Process VRAM | 匹配 NVIDIA 渲染设备后可显示整卡已用与总显存。只能取得 DXGI 数据时，标签显示当前进程用量 / 预算。 |
| Reflex / DXGI queue | 前者是输入到 GPU 的延迟采样，后者是呈现队列的估计值。二者都受接口可用性限制；`--` 表示没有当前读数。 |

**F8 紧凑面板**需在支持的 64 位游戏中安装桥接，并保持管理器运行。当前适配的 RenoDX 构建为 4.7、6.5.3、8.5.0-rc10。数值控件的实际上下限、步长和选项从已连接插件读取。桌面预览里的示例值只在预览窗口内有效。

| F8 · DLSS / 着色器 | 用途 |
| --- | --- |
| 开启神经渲染 / 屏幕状态角标 | 分别控制插件的 NR 开关，以及左上角是否显示开关状态。 |
| 总强度、结构、全局色调、局部色调 | 分别调整体处理量、纹理轮廓、全局明暗变化、局部明暗对比。 |
| 角色自动遮罩 / 角色与皮肤结构强度 | 对已识别人物区域单独控制处理程度，便于保留人脸细节。 |
| 漫反射参考白点 | 单位为尼特，决定 HDR 内容映射的参考亮度。 |
| 运动矢量 X / Y、深度方向约定 | 修正两个轴的矢量尺度或方向；深度可跟随游戏标志、强制常规或反向，取决于原插件公开选项。 |
| HUD / UI 校正、超分辅助管线 | 前者控制界面保护，后者是部分构建公开的实验性超分开关。 |
| NR 预设 / NR 风格 | 预设选择插件提供的参数组合。风格列表为默认、自然、电影感时，A / B / C 为这三个风格的快捷选择。 |
| ReShade 着色器 | 总开关和已加载 `.fx` 提供的可调项；变量名、范围、单位取决于具体着色器。状态页显示桥接和插件提供的运行信息。 |

## Feeder 实时参数

通过 F8「Feeder」页调节已适配的 **64 位 Feeder 1.17.0**。先在 Feeder 自己的 Home 页面启用有效工作模式。参数从 `dlss5-feed.cfg` 回读，管线运行时约每 60 个已送达帧重新读取配置。

| 参数 | 范围 | 作用 / 生效条件 |
| --- | --- | --- |
| 工作分辨率 / 工作锐度 | 50–100% / 0–1 | 工作尺寸影响处理像素数，锐度影响放大后的边缘。此实时接口中仅 DX11 可写。 |
| 工作分辨率上采样 | 0 双线性、1 FSR 1、2 DLSS SR | 决定将工作画面放大回输出尺寸的方法。实时切换仅 DX11。 |
| 运动矢量 X / Y 缩放 | 各 −2 至 2 | 按轴缩放运动数据，负值可反转方向。可用镜头平移观察轮廓拖影。 |
| HDR 色彩约定 / 深度方向 | 各为 −1、0、1 | HDR 依次为自动、强制 SDR、强制 HDR；深度依次为自动、常规、反向。 |
| HDR10 桥接 / HDR 参考白点 | −1 自动、0 关、1 开 / 50–1000 尼特 | 在 HDR10 和线性处理之间转换并设定参考白点。此桥接仅限 64 位 DX11。 |
| 输出稳定器保持强度 | 0–1 | 0 关闭；提高后静止位置会更久保留原输出，用于减轻纹理闪动。 |
| 稳定器变化容差 | 0–1 | 决定多大像素变化仍视为静止。过高时，缓慢运动的内容可能跟随不及时。 |
